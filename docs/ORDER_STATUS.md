# 订单状态及积分奖惩规则
## 1. 核心说明
- 角色定义：a = 吃货（订单创建方）、b = 饲养员（订单承接方）
- 积分规则：奖励为正分，惩罚为负分，无奖惩为0分
- 状态类型：中间态（可继续操作）、终态（不可再操作）

## 2. 订单状态与积分奖惩映射表
| 业务行为 | 对应原子状态（唯一标识） | 状态类型 | 说明 | 积分规则（示例） | 奖惩类型 |
|----------|--------------------------|----------|------|------------------|----------|
| a 创建订单 | PendingAccept（待接单） | 中间态 | 订单初始状态，等待b接单 | 0 积分 | 无 |
| b 接受订单 | InProgress（进行中） | 中间态 | b确认接单，订单进入执行阶段 | 0 积分 | 无 |
| b 拒绝订单 | Rejected（已拒绝） | 终态 | b明确拒绝承接该订单，订单完结 | 0 积分 | 无 |
| b 完成订单 | BreederFinished（b 已完成） | 中间态 | b完成服务操作，等待a确认结果 | 0 积分 | 无 |
| b 特殊原因关闭订单 | BreederClosed（b 主动关闭） | 终态 | 仅b已接单后可触发，因特殊原因终止订单 | -8 积分（主动终止服务） | 惩罚 |
| a 确认完成订单 | ConfirmedFinished（a 确认完成） | 终态 | a确认b服务完成，订单核心成功完结 | +10 积分（基础服务分） | 奖励 |
| a 确认未完成订单 | ConfirmedUnfinished（a 确认未完成） | 中间态 | a确认b服务未完成，需b重新处理 | -5 积分（服务不达标） | 惩罚 |
| 超时b未接单 | Timeout（已超时） | 终态 | 订单创建后超时，b未接单，系统自动触发 | -3 积分（响应不及时） | 惩罚 |
| 未接单时a取消订单 | Cancelled（a 取消 - 未接单） | 终态 | 仅订单待接单阶段，a主动取消订单 | 0 积分 | 无 |
| 系统关闭订单 | SystemClosed（系统关闭） | 终态 | 订单异常/管理员强制关闭，异常场景兜底 | 0 积分 | 无 |

## 3. 状态流转规则（核心约束）
### 3.1 禁止流转场景
1. 终态订单不允许任何状态变更（如Rejected/Timeout/SystemClosed等）
2. InProgress（进行中）状态不可直接流转至Rejected（已拒绝）/Timeout（已超时）
3. BreederFinished（b已完成）状态仅可流转至ConfirmedFinished（a确认完成）/SystemClosed（系统关闭）
4. ConfirmedUnfinished（a确认未完成）状态不可直接流转至终态（需b重新处理）
