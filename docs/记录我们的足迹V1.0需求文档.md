# 文档基础信息

- 项 详情
- 版本号 V1.0 MVP
- 开发周期 14 个自然日（2 周）
- 适用角色 前端开发、后端开发、测试工程师
- 核心目标 完成足迹模块最小闭环，验证用户记录意愿与留存提升效果，打通与现有核心系统的对接
- 核心红线 钻石与爱心积分完全隔离，无任何互通逻辑；仅已绑定 group 的用户可使用

## 一、版本边界（必须严格遵守）

### 1.1 本版本必须完成的功能

- 足迹模块入口权限控制与页面跳转
- 足迹主页面基础框架 + 顶部数据概览区
- 「我们的故事」Tab 基础全功能（3 个免费默认分组、订单自动同步草稿、手动记录、点赞评论）（补充：限于资质问题，前端暂时不开放子功能）
- 底部操作栏基础功能（快速记录、生成海报）
- 钻石基础体系（获取、消耗、流水记录）
- 与现有系统（订单、签到、用户、group 体系）的全量对接

### 1.2 本版本暂不开发的功能

- 「我们的成就」Tab 全量功能（成就卡、徽章、解锁打卡）
- 付费主题分组、自定义分组功能
- 双身份专属内容与差异化文案（仅保留基础数据的身份文案）
- 补签卡、连续打卡奖励、限定活动功能
- 多人 group 适配（仅支持 2 人基础 group）
- 专属皮肤、海报模板等高阶权益

## 三、核心功能模块开发需求

### 模块 1：页面入口与权限控制

#### 1前端需求

- 入口绑定：首页「记录我们的足迹」按钮，点击跳转至足迹主页面
- 权限前置校验：点击入口时，先调用接口校验用户是否已加入有效 group
- 已加入：正常跳转至足迹主页面
- 未加入：弹出提示弹窗，文案「请先绑定好友 / 吃货关系，即可解锁共同足迹」，弹窗底部提供「去邀请」按钮，点击跳转至「邀请好友做客」页面
- 异常处理：接口请求失败时，提示「网络异常，请稍后重试」，不可跳转页面

#### 1后端需求

- 开发「用户 group 权限校验接口」，入参 user_id，出参：是否有有效 group、group_id、group 基础信息
- 权限规则：仅用户已加入且状态正常的 group，视为有效权限；已解散 / 已退出的 group，视为无权限
- 接口安全：添加用户身份校验，防止越权访问

### 模块 2：足迹主页面 - 顶部数据概览区

#### 2前端需求

- 页面布局：顶部固定展示概览区，高度适配移动端，与首页粉系风格统一
- 展示元素（按顺序）：
- group 头像区：展示 group 内 2 个用户的头像，拼成爱心样式，点击弹出 group 选择器（本版本仅支持 1 个 group，选择器仅做占位，后续版本迭代）
- 核心数据卡片：横向排列 4 项数据，分别是「一起吃饭总天数」「累计投喂总次数」「连续打卡天数」「总记录数」，其中「累计投喂总次数」做身份差异化文案
- 饲养员视角：「你已为吃货累计投喂 XX 次」
- 吃货视角：「你已收到饲养员累计投喂 XX 次」
- 连续打卡进度条：展示当前连续打卡天数，进度条按「连续 7 天」为一个节点计算进度，进度颜色与首页粉色统一
- 徽章展示区：本版本仅做占位，展示默认空徽章样式，不做点击交互
- 数据刷新：页面加载、完成记录提交后，自动刷新概览区所有数据
- 异常处理：数据加载失败时，展示骨架屏，重试按钮点击后重新请求接口

#### 2后端需求

- 开发「足迹概览数据查询接口」，入参 user_id、group_id，出参上述 4 项核心数据、连续打卡进度、group 用户信息（目前已存在get_group_info 接口，包含「一起吃饭总天数」「累计投喂总次数」）
- 数据统计规则：
- 一起吃饭总天数：group 内完成订单的去重日期总数
- 累计投喂总次数：group 内已完成的投喂订单总数
- 连续打卡天数：group 内用户连续提交有效记录的天数，断签后重置为 0
- 总记录数：group 内已提交的正式记录总数
- 身份校验：接口内判断用户身份，返回对应差异化的文案字段
- 性能要求：接口响应时间≤200ms，数据提前做预统计，避免实时联表查询

### 模块 3：核心 Tab - 我们的故事（基础版）

#### 3前端需求

- 布局结构：左侧固定分组导航栏，右侧对应分组的记录列表，上下滑动不影响导航栏
- 分组导航栏：
- 默认展示 3 个免费分组：「干饭日常」「投喂日记」「专属纪念日」
- 高亮展示当前选中的分组，有未确认草稿的分组，添加红点提示
- 点击分组，右侧切换对应记录列表
- 记录列表规则：
- 按记录时间倒序排列，最新记录在顶部
- 单条记录卡片展示内容：发布人头像 + 昵称、发布时间、图片（1-9 张，瀑布流展示）、文案内容、地点、点赞按钮 + 点赞数、评论按钮 + 评论数
- 交互规则：
- 点击图片可预览大图，支持左右滑动
- 点击点赞按钮，可点赞 / 取消点赞，实时更新点赞数
- 点击评论按钮，弹出评论弹窗，可查看所有评论、发布评论
- 仅自己发布的记录，展示「编辑」「删除」按钮
- 自动草稿功能：
- 进入 Tab 时，若有未确认的草稿，顶部弹出高亮提示条，展示「你有 1 条未确认的干饭记录，快去看看吧」
- 草稿卡片展示默认内容、「一键确认」「编辑补充」按钮
- 点击「一键确认」：直接调用接口生成正式记录，关闭提示条，刷新列表
- 点击「编辑补充」：跳转至记录编辑页，自动填充草稿默认内容
- 手动记录功能：
- 编辑页必填项：归属分组选择、1-9 张图片、记录时间（默认当前时间）
- 编辑页选填项：文案内容、地点、@group 内成员
- 提交校验：必填项为空时，禁止提交，提示对应缺失内容
- 提交成功后，跳转回列表页，刷新列表，弹出「记录提交成功」提示
- 容量规则：
- 每个分组默认 50 条容量，记录数达到上限时，隐藏「新增记录」按钮，提示「该分组记录容量已满，可消耗钻石解锁更多容量」，提供「解锁扩容」按钮
- 点击「解锁扩容」，弹窗展示容量档位、所需钻石，确认后扣除钻石，扩容成功
- 空状态处理：
- 分组内无记录时，展示空状态插画 + 文案「这个分组还没有记录哦，快去记录你们的故事吧」，底部「快速记录」按钮
- 无任何草稿、无任何记录时，展示全局空状态，引导去完成订单生成草稿

#### 3后端需求

- 分组相关接口开发：
- 分组列表查询接口：入参 group_id，出参 3 个默认分组的信息（id、名称、类型、当前记录数、最大容量、状态）
- 分组容量扩容接口：入参 user_id、group_id、record_group_id、扩容档位，校验钻石余额，扣除对应钻石，更新分组最大容量，记录钻石流水
- 记录相关接口开发：
- 记录列表查询接口：入参 group_id、record_group_id、页码、页长，出参记录列表全字段
- 记录提交 / 编辑 / 删除接口：入参记录全字段，做权限校验，仅发布人可编辑 / 删除，提交后更新分组当前记录数
- 草稿确认接口：入参草稿 id、是否编辑、编辑后的内容，将草稿转为正式记录
- 记录点赞 / 评论接口：入参 record_id、user_id，做点赞 / 取消点赞、评论提交 / 查询操作
- 订单自动同步草稿逻辑：
- 触发时机：group 内订单状态更新为「已完成」时，自动触发
- 生成规则：在「干饭日常」分组生成一条草稿记录，填充订单 ID、菜品名称、下单时间、默认文案、关联用户信息
- 幂等控制：同一个订单仅生成一条草稿，避免重复生成
- 权限控制：
- 仅 group 内成员可查看 / 操作对应分组的记录
- 仅发布人可编辑 / 删除自己的记录
- 扩容操作仅 group 内成员可执行，扩容后 group 内共享
- 数据校验：
- 记录提交时，校验必填字段，过滤违规内容
- 扩容时，校验钻石余额，不足时返回错误码，不执行扩容
- 容量满时，禁止提交新记录，返回错误码

### 模块 4：底部固定操作栏（基础版）

#### 4前端需求

- 布局：页面底部固定展示 3 个按钮，宽度均分，与底部导航栏无重叠
- 按钮功能：
- 快速记录：点击跳转至记录编辑页，默认选中「干饭日常」分组
- 生成海报：点击跳转至海报生成页，默认选择基础模板，展示核心概览数据 + 最新 1 条记录，支持保存至相册，保存成功后提示「海报已保存至相册，分享可获得钻石奖励」
- 成就图鉴：本版本置灰，点击提示「功能即将上线，敬请期待」
- 交互：按钮点击有按压反馈，样式与首页风格统一

#### 4后端需求

- 海报生成接口：入参 user_id、group_id、模板类型，返回海报图片地址
- 分享奖励发放接口：用户分享成功后调用，入参 user_id，校验当日分享上限，发放对应钻石，记录流水
- 规则：每日首次分享奖励 20 钻石，后续每次 5 钻石，每日上限 10 钻石

### 模块 5：钻石基础体系

#### 5前端需求

- 钻石余额展示：概览区、解锁扩容弹窗、签到页面，同步展示用户当前钻石余额
- 钻石流水页：本版本仅做基础入口，展示钻石获取 / 消耗记录，按时间倒序排列，展示时间、类型、数量、余额
- 异常处理：钻石扣除失败时，提示「操作失败，请稍后重试」，余额不发生变化

#### 5后端需求

- 钻石相关接口开发：
- 钻石余额查询接口：入参 user_id，出参当前余额、累计获取 / 消耗
- 钻石流水查询接口：入参 user_id、页码、页长，出参流水列表
- 钻石奖励发放接口：内部接口，供签到、记录、分享等场景调用，发放对应钻石，记录流水
- 钻石扣除接口：内部接口，供扩容、解锁等场景调用，校验余额，扣除钻石，记录流水
- 钻石获取规则（本版本）：

- 渠道 规则 每日上限
- 每日签到 普通签到 5 钻石 / 天 无
- 提交有效记录 5 钻石 / 条（含图片 + 文案） 20 钻石 / 天
- 分享海报 首次 20 钻石，后续 5 钻石 / 次 10 钻石 / 天
- 钻石消耗规则（本版本）：

- 渠道 规则 生效范围
- 记录容量扩容 50 条→100 条：30 钻石
- 100 条→200 条：50 钻石
- 200 条→无限：200 钻石 对应分组永久生效
- 数据安全：
- 钻石流水 100% 可追溯，每一笔发放 / 扣除都有唯一流水号、关联场景、操作人
- 接口做幂等设计，防止重复发放 / 扣除
- 余额字段做乐观锁，防止并发问题导致的余额错误

### 模块 6：与现有系统的对接

#### 6前端需求

- 与现有签到系统对接：钻石不足时，跳转至现有签到页面，签到成功后返回足迹页面，同步更新钻石余额
- 与现有订单系统对接：空状态时，跳转至「看看想做点啥」页面，完成订单后返回足迹页面，同步生成草稿
- 与现有用户 /group 系统对接：获取用户身份、group 信息，同步权限状态

#### 6后端需求

- 与现有订单系统对接：监听订单状态变更事件，订单完成后触发草稿生成逻辑
- 与现有签到系统对接：签到成功后，调用钻石发放接口，发放对应钻石
- 与现有用户 /group 系统对接：复用用户身份、group 信息、权限体系，不重复开发
- 与现有内容审核系统对接：用户上传的图片、文案，自动触发违规内容审核，违规内容禁止提交
